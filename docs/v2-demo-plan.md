# v2 示範關卡（D01《守靈夜消失的遺囑》）製作計畫

狀態：2026-11-19 訂。分支 `v2-demo`。規劃與驗收由主模型負責；實作派給 Opus（邏輯、畫面）與 Sonnet（機械性工作）。

## 1. 交付的定義

「交付」＝使用者能在 `E:\coding4\Sherefox-build-v2` 啟動並實際玩到的東西，附啟動方式與截圖。只有無頭測試通過的里程碑不算交付，做完要直接接著做下一個。每個里程碑結束時通知「Sherefox遊戲企劃」。

## 2. 架構決定

1. **D01 是 `steps` 表裡的一章**，不是標題入口後面一串臨時的畫面切換。v1 的 `paper`、`vn` 步驟圖直接重用；D01 專屬的步驟用新的 kind（`d1warmup`、`d1investigate`、`d1carry`、`d1debate`、`d1result`）。跨步驟要用的狀態（找到的調查點、鑑定與剩餘次數、筆記、私下的看法、攜帶選擇、熱身結果、論戰結果）放在 world 訊號或集合。
2. **規則只有一個判準**：參考模型 `ref/src/sherefox_ref/v2/`。遊戲內的任何規則判斷（含 M4 的結局分支）先寫進 ref 並以章節的表格測試，再讓流圖對上 ref。UI 不自己發明判斷。
3. **引擎不拒絕不合法的行動**，所以「UI 只提供合法的選擇」必須有測試：腳本路線之外，另以隨機合法點擊的 UI fuzz 對 ref（M5）。
4. **隱藏數值**：不顯示塞德里克的量表數值與門檻、真相度、聲譽總和；模糊預兆不顯示姿態。每個新畫面驗收時逐一檢查寫到 UI 的 port。
5. **v1 不動**：v1 的檢查全過是每個里程碑的條件。`full_run.atrec` 的雜湊在本分支與 main 不同（新增的訊號與標題入口都會改變狀態雜湊），所以本分支的基準是「v1 檢查全過」而不是 `027fc534ef3847e4`；main 仍以該雜湊為準。
